# Superpowers Workflow: Инженерный подход ИИ

При работе над сложными задачами (создание новых фичей, рефакторинг, архитектурные изменения) ты **ОБЯЗАН** строго следовать алгоритму из 7 фаз. Запрещено перепрыгивать через фазы или сразу выдавать весь код без анализа.

## Phase 1: Socratic Brainstorming (Сократический анализ)
- Внимательно изучи текущий код с помощью инструментов (чтение файлов, поиск). 
- Подумай о возможных побочных эффектах твоего решения. 
- Задай пользователю уточняющие вопросы, если требования неоднозначны.

## Phase 2: Detailed Planning (Детальное планирование)
- Разбей задачу на микро-задачи (шаги).
- Вызови режим планирования (Planning Mode) и создай артефакт `implementation_plan.md`.
- Опиши, какие конкретные файлы будут изменены (`[NEW]`, `[MODIFY]`, `[DELETE]`).
- Обязательно дождись одобрения плана от пользователя, прежде чем писать первый байт кода.

## Phase 3: Test-Driven / Verification First (Фокус на проверку)
- Сначала продумай, как именно мы будем проверять, что код работает. 
- Напиши скрипт тестирования (или юнит-тест, или опиши шаги для ручного теста в браузере), прежде чем писать бизнес-логику.

## Phase 4: Isolated / Atomic Execution (Атомарное выполнение)
- Изменяй строго один логический блок/компонент за раз.
- Не пытайся переписать 10 файлов одним огромным блоком.
- Вноси изменения поэтапно, отмечая прогресс в артефакте `task.md`.

## Phase 5: Parallel Thinking (Избегание "туннельного" зрения)
- Когда ты фокусируешься на одном файле, не забывай о связях с базой данных (Prisma/Drizzle) и другими компонентами.
- Если меняется модель БД, сразу планируй правки в API-маршрутах и UI.

## Phase 6: Systematic Code Review (Само-ревью кода)
- После написания кода перепроверь его.
- Убедись, что нет синтаксических ошибок, забытых импортов или "заглушек" (`// TODO: implement later`).
- Если возможно, запусти проверку типов или сборку (например, `npm run build` или `npx tsc --noEmit`).

## Phase 7: Final Delivery (Сдача работы)
- Убедившись, что всё работает, подготовь для пользователя краткий отчет (Walkthrough).
- Объясни, как запустить и проверить результат.
